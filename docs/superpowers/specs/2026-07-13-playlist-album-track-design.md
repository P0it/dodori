# 플레이리스트 재정의 — 하루=앨범, 장소=트랙

날짜: 2026-07-13
상태: 설계 확정 (구현 전)

## 문제

플레이리스트 탭의 목적이 흐렸다. 스튜디오가 사진·게시물 아카이빙을 가져간 뒤로 "이 탭은 뭘 하는 곳인가"가 남았다.
원인은 둘이다.

1. **메타포가 한 칸 위였다.** 트랙 = 데이트 하루, 플레이리스트 = 한 달(자동). 실제로 사람이 기억하는 단위는
   "그날 어디어디 갔다"이고, 장소가 곡에 가깝다.
2. **플레이리스트를 만든 뒤에 할 일이 없었다.** `playlists`/`playlist_places`는 장소 모음이지만,
   그 장소가 다음 데이트로 이어지는 경로가 앱 어디에도 없다. 만들 수 있고 볼 수만 있었다.

## 결정

### 개념 계층

| 개념 | 뜻 | 저장소 (테이블명은 유지) |
|---|---|---|
| 트랙 | 장소 하나 (식당·카페·공원) | `places` + `track_places` |
| 앨범 | 하루 = 데이트 | `tracks` (하루 한 행) |
| 플레이리스트 | 사용자가 만드는 혼합 컬렉션 (장소 + 앨범) | `playlists` |

테이블 이름은 바꾸지 않는다. 바뀌는 것은 UI 카피와 타입/컴포넌트 이름뿐이다 — 마이그레이션 리스크를 만들지 않기 위해서.

**싱글(기념일) 개념은 폐기한다.** 기념일은 캘린더의 일이다. `anniversaries` 테이블은 캘린더가 계속 쓰므로 남기고,
플레이리스트 탭에서의 노출과 "싱글"이라는 이름만 없앤다.

### 플레이리스트의 목적: 계획 도구

플레이리스트는 **미래형**이다 — "가고 싶은 곳을 쟁여두고, 데이트 짤 때 꺼내 쓴다".
돌아보기(회상)는 스튜디오가 이미 맡고 있으므로 플리의 본업으로 삼지 않는다.

핵심 루프:

```
발견 → ♡ → (선택) 테마 플리로 정리 → 캘린더에서 날짜 잡아 앨범 생성
     → 장소 피커로 트랙 담기 → 다녀오며 done 체크 → 날짜 지나면 자동 발매
     → 사진 채움 → 아카이브에 쌓임
```

### ♡ 좋아요와 플레이리스트의 관계

스포티파이 모델을 따른다. **♡는 시스템이 자동 관리하는 플레이리스트 하나다.**

- **♡ = 저장 (분류 없음)** — 한 번 탭. 자동으로 "좋아한 장소" 시스템 플레이리스트에 쌓인다.
- **플레이리스트 = 분류 (의도 있음)** — "여름 데이트", "비 오는 날". ♡한 것 중 골라 담거나 바로 담거나.

♡는 **개인별**이다 (3역할 규약: 나=green / 상대=pink). 같은 장소를 둘 다 눌렀으면 "매칭" 배지가 붙는다 —
매칭이 곧 다음 데이트 후보라는 신호가 된다.

앨범 ♡는 기존 `tracks.liked`를 그대로 쓴다. 장소 ♡와는 다른 축이다.

## 스키마 변경 (마이그레이션 1개)

### `place_likes` (신규)

개인별 장소 ♡. "좋아한 장소" 시스템 플레이리스트의 실체.

- PK `(place_id, user_id)`
- `couple_id`를 함께 들고, RLS는 공통 술어 `public.my_couple_id()` 사용
- `created_at`

### `playlist_items` (신규) → `playlist_places` 대체

플리에 장소와 앨범이 섞여 들어가야 하므로 항목을 다형으로 바꾼다.

- `playlist_id`, `kind`('place' | 'album'), `place_id` nullable, `track_id` nullable
- CHECK 제약: `kind`에 맞는 쪽 하나만 정확히 채워질 것
- `sort_order`, `added_by` 유지
- 기존 `playlist_places` 행은 `kind='place'`로 이관 후 테이블 드롭

**앨범을 담으면 앨범 카드 한 항목으로 들어간다** (스포티파이처럼 수록곡으로 펼치지 않는다).
"이 날 코스 통째로 좋았음"을 표현할 수 있어야 하기 때문. 탭하면 그 날 앨범 상세로 이동.

마이그레이션 후 `npx supabase gen types typescript --local > src/types/database.types.ts` 재생성.

## 화면

### 플레이리스트 탭 — 세그먼트 2개

한 탭 안에서 계획과 회상을 분리한다.

**`리스트` (계획)**
- 좋아한 장소 — 시스템 플리, ♡ 개수 뱃지, 매칭 배지
- 다가오는 예정 — 아직 안 온 앨범 (기존 queue)
- 내 플레이리스트 — 테마별 목록 + 새로 만들기

**`아카이브` (회상)**
- 월별 앨범 목록 — 기존 `monthKey` 묶음 그대로

### 앨범 상세 (`track/[id]`)

수록곡 = 장소 리스트로 읽힌다. `track_places.sort_order`로 1·2·3 번호, `done`은 다녀옴 체크.
**"트랙 추가"** 버튼이 장소 피커를 연다.

### 장소 피커 (신규 모달)

탭 3개: **좋아한 장소 / 내 플레이리스트 / 검색(네이버)**.
A안의 루프를 닫는 부품. 지금은 검색밖에 없는 자리다.
고른 장소가 그 날 앨범의 트랙으로 꽂힌다.

### ♡의 위치

장소가 보이는 모든 곳 — 피커, 플리 내부, 앨범 수록곡, 장소 상세 — 에 하트 하나.
누르면 즉시 `place_likes`에 쌓이고 "좋아한 장소"에 나타난다. 분류는 나중에 해도 되고 안 해도 된다.

## 영향 범위

의존성 방향 규칙(`app/ → components/ → api/·lib/`)을 지킨다.

- **lib/** — `lib/places.ts` 신규: ♡ 매칭 판정(둘 다 눌렀는지), 플리 항목 정렬. 순수 함수, 유일한 단위 테스트 대상
- **api/** — `api/likes.ts` 신규(♡ 토글, 낙관적 업데이트), `api/playlists.ts` 확장(혼합 항목 조회/추가/삭제)
- **components/** — 장소 행(♡ 포함), 플리 항목 셀(장소/앨범 두 variant — `kind`로 분기, OCP)
- **app/** — 플리 루트 세그먼트화, `singles.tsx` 삭제, 장소 피커 모달 신규, 앨범 상세에 "트랙 추가" 연결
