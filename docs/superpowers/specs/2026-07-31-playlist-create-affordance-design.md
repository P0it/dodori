# 라이브러리 탭 — 이름 정리와 생성 동선 분리 (2026-07-31)

## 문제

플레이리스트 탭 위에서 두 개의 다른 "만들기"가 서로를 오염시킨다.

1. 캐러셀(앨범 = 데이트)에는 **자기 헤더가 없다.** 화면의 첫 헤딩인 `저장 리스트`가
   위쪽 LP들까지 덮는 라벨처럼 읽힌다
2. 그 헤더 바로 아래 첫 줄이 `+ 새 리스트 만들기`다. LP 바로 밑에 붙은 `+`라
   **"LP를 한 장 추가한다"로 오인**된다
3. 정작 앨범을 만드는 버튼은 우측 하단 FAB — 캐러셀과 시각적 연결이 전혀 없다
4. 화면 제목이 `플레이리스트`라 **아래의 `저장 리스트`와 같은 계열로 읽힌다.**
   정작 이 화면의 주인공인 앨범(데이트)이 "제목 없는 장식"으로 밀려난다

## 설계

### 이름 (4번을 푼다)

음악 메타포 그대로 **라이브러리 ⊃ 플레이리스트 + 가보고 싶은 곳**으로 위계를 세운다.

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 탭 라벨·화면 제목 | 플레이리스트 | **라이브러리** |
| 앨범 캐러셀 | (헤더 없음) | **플레이리스트** — 시간순으로 늘어선 우리 데이트 |
| 찜 목록 | 저장 리스트 | **가보고 싶은 곳** |

제목과 섹션 이름이 겹치지 않고, 주인공(데이트)이 제 이름을 갖는다.
지난 데이트는 재생됐고 앞의 데이트는 대기열 — 캐러셀의 동작과도 맞는다.

아래 섹션은 `저장 리스트`를 버리고 **`가보고 싶은 곳`** 으로 간다 — "리스트" 계열에서
아예 벗어나야 위의 `플레이리스트`와 헷갈릴 여지가 사라진다.
(담긴 장소 중엔 이미 다녀온 곳도 섞이지만, 담는 행위 자체가 "가보고 싶어서"이므로 이름은 맞다.)

**내부 이름은 바꾸지 않는다.** `playlists` 테이블·`usePlaylists`·`/modals/new-playlist`·
`playlist/custom/[id]`·`PlaylistPickerSheet`은 그대로 두고 **UI 카피만** 바꾼다.
지금 리네임하면 마이그레이션·라우트까지 번져 이번 범위를 벗어난다.
→ 용어 대응(UI "가보고 싶은 곳" = 코드 `playlists`)은 CLAUDE.md에 한 줄 남긴다.

### 생성 동선 (1~3번을 푼다)

각 영역이 **자기 헤더와 자기 `+`** 를 갖는다.

| 영역 | 헤더 | 생성 진입점 |
|---|---|---|
| 앨범 캐러셀 | `플레이리스트` (신설) | 헤더 우측 `+` **+** 캐러셀 꼬리의 빈 앨범 카드 |
| 찜 목록 | `가보고 싶은 곳` | 헤더 우측 `+` |

1. **캐러셀 위에 `플레이리스트` 헤더 신설.** 우측 `+` → `/modals/create-track`
2. **`가보고 싶은 곳` 헤더 우측에 `+`** → `/modals/new-playlist`.
   목록 첫 줄의 `+ 새 리스트 만들기` 행은 **제거** (오인의 진원지)
3. **캐러셀 맨 끝에 빈 앨범 `+` 카드.** 점선 테두리 + 가운데 `+`, 탭하면 `/modals/create-track`
4. **우측 하단 FAB 제거**

`SectionHeader`는 이미 `onMore`(더보기 텍스트)를 받는다 — 쓰는 곳이 없으므로
`onAdd`(우측 `+` 아이콘)로 **대체**한다. 새 prop을 늘리지 않는다.

### 꼬리 + 카드까지 스크롤하는 비용

캐러셀은 날짜 오름차순이고 포커스는 "오늘 최근접"이라, 꼬리까지의 거리는
**앞으로 잡힌 데이트 개수**다. 과거가 아무리 쌓여도 오른쪽 꼬리는 길어지지 않는다(대개 1~3장).
그래도 0으로 만들기 위해 헤더 `+`를 둔다 — **헤더 `+`는 항상 닿는 길, 꼬리 카드는 의미를 보여주는 길.**
입구가 둘이지만 둘 다 앨범 영역 안이라 교차 오인이 없다.

검토했으나 버린 대안:

- 캐러셀 위에 절대배치로 `+` 칩 고정 → 이웃 카드를 가리고, 스크롤 면 위의 고정 요소가
  "이것도 앨범인가?"를 다시 만든다. 문제를 옮길 뿐
- 미래 앨범 3장 초과일 때만 헤더 `+` 노출 → 조건부 UI로 버튼이 사라지고 임계값 상수가 생긴다 (YAGNI)

## 시각

- 빈 앨범 카드: `CARD`(176) 정사각, `borderRadius: 6` — 실제 앨범과 동일 규격.
  점선 테두리 `color.hairline`, 배경 `color.surface1`, 가운데 `+` `color.sub`.
  글로우는 주지 않는다 (활성 카드의 표식이므로)
- 앨범이 아닌 슬롯이므로 `active` 계산·제목 표시 대상에서 제외한다.
  캐러셀 하단의 제목/날짜는 실제 앨범일 때만 뜬다
- 헤더 `+`: 24px 아이콘 `color.sub`, 히트 영역 44 이상

## 영향 범위

- `src/components/CoupleTabBar.tsx` — 탭 라벨 `플레이리스트` → `라이브러리`
- `src/app/(tabs)/playlist/index.tsx` — 화면 제목, 헤더 신설, `+` 배선, 만들기 행·FAB 제거
- `src/components/AlbumCarousel.tsx` — 꼬리 슬롯(`onCreate` prop), 인덱스/제목 처리
- `src/app/modals/new-playlist.tsx` — 카피만 맞춘다(`새 리스트` → `가보고 싶은 곳 추가`).
  "리스트는 데이트가 아니라 장소를 모아요" 안내 문구는 **유지** — 같은 오인을 막는 안전망이다
- `CLAUDE.md` — 4탭 서술의 탭 이름, 용어 대응 한 줄
- 라우트 경로(`/(tabs)/playlist`)와 DB·훅 이름은 **변경 없음**
- 기록 0개 첫 실행(`FirstTrackHero`) 경로는 **그대로** — 캐러셀 자체가 안 뜬다

## 검증

- 앨범 0개: 히어로만. 섹션 헤더·캐러셀·FAB 없음 (기존과 동일)
- 앨범 1개(과거): 꼬리 `+` 카드가 바로 오른쪽에 보인다
- 미래 앨범 3개: 포커스는 오늘 최근접, 헤더 `+`로 스크롤 없이 생성 가능
- 가보고 싶은 곳 0개: 헤더와 `+`만 보이고 목록은 비어 있다 — 진입점이 헤더 `+` 하나뿐인지 확인
- 탭바에 `라이브러리`가 뜨고 탭 이동이 정상 (라우트명은 그대로이므로 회귀 없음)
- `npm run typecheck` / `npm test` 통과
